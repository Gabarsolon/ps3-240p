# v1.5.0-dev18: sample alternate source rows through native scanout pitch

**PROVEN (private 4.93 trace):** native pitch writer `0x8000369c` programs
the source-fetch pitch field at head-relative PCRTC `+0x820`. Display setup
`0x800005e4` calls it when the supplied pitch changes. Its instruction at
`0x800036c8` masks the supplied pitch before merging it with preserved
register bits. The source dimensions and FP output raster are separate.
Sources: private `sysmgr_ss.elf` at those addresses; ignored decompilation.
No Sony instruction listing is included here.

**INFERRED (experiment):** doubling only the hardware fetch pitch should
sample rows 0, 2, ..., 1078 of an unchanged 1080-line source during the
540-row progressive output. This is nearest-row subsampling, not a filtered
downscale. Renderer pitch and the native request's cached pitch stay stock.
The last sampled pixel lies within the original source's memory extent.

**PROVEN (implementation):** a generated PPC rotate/mask instruction doubles
the native writer's pitch argument. The backend refuses source pitches at
or above 32768 or without eight-byte alignment, preventing overflow of the
native 16-bit field. Complete identity now covers eight original/neighbor
qwords (hash `d059dd47ffaf6c27`); four code qwords change. Original code is
saved at runtime. Source: `app/source/hd540_scale.c` and backend preflight.

**PROVEN (cache/telemetry):** the self-authored wrapper flushes all four
edited instruction lines and reads native PCRTC pitch/height in addition to
the FP controls. Its 288-byte code and 48-byte RW telemetry stay within the
same checked unused mapped-page padding. Candidate readiness requires the
measured pitch field to equal twice the saved pitch; recovery requires the
stock pitch before descriptor/padding cleanup. Sources:
`plugin/hd540_cache.S`, `app/source/hd540_cache.c`, `plugin/vsh_hd540.c`.

**PROVEN (recovery):** code/timing/AVI restoration precedes the stock 720p
then saved 1080i requests. The changed intervening pitch makes the native
writer program the original hardware pitch on recovery; readback is required.
Partial writes, foreign changes and failed cleanup retain checked recovery.
The active hold is still 15 seconds. Source: service/backend and their tests.
