# v1.5.0-dev13: progressive 540-line output with a bounded source window

Checkpoint: 2026-11-14. Full-picture fitting is unverified at this checkpoint.

**PROVEN (prior observations):** dev11 produced visible, receiver-detected
1920x540/progressive output but showed a cropped/stretched source. Restoring
field fetching in dev12 made the candidate black. See [dev11](HD540_DEV11.md)
and [dev12](HD540_DEV12.md).

**PROVEN (private static trace):** placement routine `0x80002ca4` derives
the 1080-line source valid window independently of the FP raster record.
Instruction `0x80002f4c` supplies the vertical scaling/filter flags written
to the native `+0x880` control. Instruction `0x80003058` merges the vertical
valid-window end written to `+0x818`. Instruction `0x80003104` supplies the
line-step constant written to `+0x89c`. Evidence: private 4.93 binary at these
addresses and ignored `local_only/activation/sysmgr_scaler_raw.asm`.
No Sony instruction listing is published here.

**CLAIMED (Nouveau definitions):** bit `0x10` enables vertical scaling and
`0x1000` selects vertical bilinear interpolation for the related `+0x880`
control. Source: [Linux v6.12 nvreg.h](https://github.com/torvalds/linux/blob/v6.12/drivers/gpu/drm/nouveau/dispnv04/nvreg.h).
**INFERRED:** combining that enable with a 540-line valid window and a 2.0
source-line step may fit the full source without re-enabling interlace.
The RSX line-step format and execution must be tested functionally.

**PROVEN (implementation):** dev13 returns to dev11's matched progressive
raster and progressive source fetching. New `hd540_scale.c` fingerprints
six code/neighbor qwords and saves originals at runtime. It generates three
PPC instructions to set scaling/filter flags `0x1010`, valid-window end 539,
and line-step constant `0x20000000`. Each write preserves the other half of
its aligned qword. No Sony instruction bytes are embedded in this module;
the offline fixture reuses existing legacy baseline macros and otherwise
uses self-authored OR/NOP instructions. The live identity is a hash.

**PROVEN (guards/recovery):** resolve/apply/readback check mappings and all
fingerprinted words. Unknown changes are refused. Partial writes restore
checked original code; failed restoration retains recovery. Backend preflight
and completion check scaler code in addition to raster/AVI state. Recovery
restores all three modules before any stock mode request. Controls do not
apply the source-window patch. Sources: `app/source/hd540_scale.c`,
`plugin/vsh_hd540.c` and `plugin/hd540_service.c`.

**PROVEN (checks):** host suite, all 24 startup cases and private 4.93
fingerprints pass, including the new source-window code fingerprint.
Tests decode the generated instructions, verify adjacent-word preservation,
all three scaler store failures and all fourteen combined store failures,
rollback/retry, changed mapping and unknown code/neighbor refusal. The compiled
helper's loader contract and decrypted package-member checks pass. Sources:
`tests/test_hd540_scale.c`, `tests/test_vsh_hd540.c`, `tools/test_app.py`,
`tests/audit_plan.c`, `tests/test_plugin.py` and the package builder.

**PROVEN (artifact/deployment):**
`build/hd540/deliverables/CRT-Toolset-1.5.0-dev13.pkg`, SFO 01.62,
305248 bytes, SHA-256
`099bb7e2b077b42cd0fe2e526735ba11c94007261beeccf6c615109e6d10a464`.
App, SFO and both helpers were installed at idle XMB with checked dev12
hashes, backups and byte readback. A VSH restart and verified empty-slot
helper load activated HD5C / `crt_hd540.v12.ready`. Evidence: ignored
`local_only/hd540/dev13/` deployment, restart and automatic logs.
Flash/firmware/settings installation, clocks and direct MMIO writes are excluded.

**UNKNOWN:** full-source fit, actual code execution beyond RAM readback,
receiver scan type/refresh and compatibility beyond the tested capture setup.
These require visible geometry plus a separate receiver-status observation.

**PROVEN (live observation):** both stock controls passed. The candidate had
22/22 positive mature picture samples, recovered visibly and reached
DONE/detail 0. Inspection of `candidate-024-state3.jpg` still showed a cropped,
stretched upper XMB. Evidence: ignored
`local_only/hd540/automatic/20261114-140559/`. The three scaler RAM writes
reported success, but this did not prove effective scaling or code execution.

**PROVEN (subsequent static finding):** the raster's FP timing-generator
control selects mode `0x100`, and `0x80002ca4` copies those mode bits into
the native FP control before applying scale flags. **CLAIMED (Nouveau):**
mode `0x100` is CENTER, while mode zero is SCALE.
**INFERRED:** CENTER may bypass the requested source scaling. Dev14 tests
clearing only these mode bits with the same guarded source-window changes.
