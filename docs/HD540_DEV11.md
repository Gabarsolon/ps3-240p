# v1.5.0-dev11: matched progressive raster and source-fetch control

Checkpoint: 2026-11-14. Live 540p remains unverified at this build checkpoint.

**PROVEN (prior live result):** the dev10 progressive control showed a
readable 720p picture but the combined candidate was black in all 22 mature
automatic capture samples. Both restored stock 1080i. See
[dev10](HD540_DEV10.md) and [automation evidence](HD540_AUTOMATION.md).

**PROVEN (private static trace):** raster writer `0x80003bcc` sends record
fields 4..8 to the FP vertical display-end, total, marker, sync-start and
sync-end registers. It sends packed field 11 to `0x6808f8`. Source-fetch
setter `0x80003a24` uses metadata field 1 to select the PCRTC interlace path.
The placement routine `0x80002ca4` derives the valid window from source
dimensions and metadata. The validator at `0x80025e08` rejects source height
above the metadata height. Evidence: private 4.93 `sysmgr_ss.elf` at those
addresses and ignored Ghidra outputs in `local_only/activation/`.

**PROVEN (independent register names):** the Nouveau definitions identify
FP vertical display-end/total/sync registers at `0x680800..0x680810`.
Source: [Linux v6.12 nvreg.h](https://github.com/torvalds/linux/blob/v6.12/drivers/gpu/drm/nouveau/dispnv04/nvreg.h).
**INFERRED:** the corresponding RSX raster values use end-counter coordinates,
consistent with stock 720p/1080p records and the external modeline arithmetic.

**INFERRED (failure mechanism to test):** dev10's even full-frame total,
retained 1080i primary sync edges and interlaced source path did not establish
a progressive waveform. A complete progressive vertical raster plus a clear
source-fetch interlace flag is a better isolation than editing the total
and packed field alone. This is not a claim of a proven electrical cause.

**PROVEN (implementation):** each audited 1080i profile now changes five
ordinary-RAM qwords: clear its source-interlace metadata flag; set raster
display-end/total to 539/561; marker/start to 542/541; sync end to 546 while
preserving its neighboring horizontal field; and packed vertical range to
546/541. This represents the independent 540-active/562-total modeline with
physical VSYNC positions 542..547. Clock and horizontal timing remain stock.
Source dimensions stay 1920x1080 to avoid the proven validator rejection.
AVI-builder code still produces VIC 0; the transmitter template is unchanged.
Sources: `app/source/hd540_patch.c` and `hd540_hdmi.c`.

**UNKNOWN:** whether full source-window coordinates fit the shorter output,
whether the picture is cropped, actual sync and transmitter acceptance. A
positive picture requires subsequent scan-type and geometry checks. Native
mode/cache readiness still cannot prove progressive output.

**PROVEN (checks):** all host tests, 24 startup scenarios and private 4.93
fingerprints pass. Scope/rollback tests cover all ten changed timing words
and all eleven combined timing/AVI write-failure positions. Full source
dimensions, SD records, clock and unaffected horizontal fields remain checked.
The compiled helper's loader/thread-exit contract and decrypted package
members pass verification. Protocol HD5A / `crt_hd540.v10.ready` separates
the new recipe from the old resident helper.

## Live result

**PROVEN (undisturbed capture):** stock roundtrip, 720p AVI control and the
new candidate passed helper/pixel checks and all recovered visibly to stock.
The candidate had 22/22 positive mature picture samples. Evidence: ignored
`local_only/hd540/automatic/20261114-135319/report.json` and saved frames.
**PROVEN (visual inspection):** representative candidate frame
`candidate-023-state3.jpg` shows a vertically stretched/cropped upper portion
of the XMB. Pixel visibility is not a full-picture pass.

**PROVEN (separate receiver observation):** repeating the candidate with one
live status query returned width 1920, height 540, signal present, raw scan
flag `0x07`, interpreted as progressive by the upstream mapping. The helper
subsequently completed restoration with DONE/detail 0. Evidence: ignored
`local_only/hd540/dev11/candidate-scan.json`, `measure-stdout.log` and
`measure-helper.log`. See [capture status](CAPTURE_INPUT_STATUS.md) for the
firmware-specific interpretation caveat; refresh is not measured.

**INFERRED:** this establishes a detected progressive 540-line signal on the
tested setup, with source-window fitting still incomplete. The next isolation
keeps the matched FP timing and restores field fetching; it must check both
the whole picture and receiver scan type. Do not claim the cropped result
as completed 540p support.
